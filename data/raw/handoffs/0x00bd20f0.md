## The original source shape (evidence from the pack itself)

The pack's unit already contains the true FO3 idiom for this exact class (an already-verified
neighbour, `namespace f3m_00bcf290::Slot1ThreadBC`, unit line 6215):

```cpp
struct Semaphore {
    volatile LONG pending; HANDLE handle; LONG maximum;
    __forceinline void Initialize(LONG initial, LONG limit) {
        pending = initial;
        maximum = limit;
        handle = CreateSemaphoreA(0, pending, maximum, 0);   // member reads, NO accessor
    }
};
```
I compiled the pack unit (SP1, same flags) and its asm confirms this shape emits
`mov ecx,[esi]` for the pending read both **out of line** (`?Initialize@Semaphore@...`) and
**inlined** (`??0BSTaskletManager@...`): in both, eax is occupied (by the `limit` parameter
and by the zero constant, respectively), so pending takes ecx. In our function the zero lives
in **ebx** (kept across the two 256-iteration loops), so eax is free and the temp takes eax.
That is the whole difference; the `maximum` read constant-folds to `push 1` and consumes no slot.
