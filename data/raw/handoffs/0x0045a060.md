## What the function is

`Owner::FUN_0045a060(int key, int value)` — thiscall, `ret 8`. Walk the intrusive list at
`this+4`; find the entry whose `key == key`; on hit either free it (`refs == 0 && value == 0`:
`list.FUN_00421610(&item)` then `DAT_01090a78.FUN_0086ba60(item)`) or overwrite `entry->value`;
on miss, if `value != 0`, allocate 12 bytes from `DAT_01090a78.FUN_0086b930`, fill key/value and
insert with `list.FUN_0061c430(&item)`.

Both calls take the entry pointer **by reference** → `item` is an address-taken local whose home
is the *dead `key` parameter slot* (`[E+4]`, printed as `[esp+0x10]` in the loop and `[esp+0x14]`
before the insert push). The loop's second call site reuses the same temp slot (disjoint ranges).

## The two residues (both confirmed with f3check and with a fast local oracle)

```
ORIG 001a  mov esi, ecx            ; item = the value just loaded into ecx (a COPY)
OURS 001a  mov esi, [eax]          ; item reloaded from the node

ORIG 0043  lea ecx,[esp+0x14] ; push ecx ; mov [eax],edi (key) ; mov ecx,ebx
           ; mov [esp+0x18],eax (item = new) ; mov [eax+4],esi (value) ; call
OURS       ... the `item = new` store lands BEFORE the push (and before the key store)
```

The target therefore reads: alloc → key store → `item = ne` → value store → call, i.e. the
home store is a *source statement between the two field stores*, and the `push` is hoisted
above it. Our draft's `Entry* ni = ne;` (a reference temp for the call) stores it too early.

## The mechanism (why it resists)

**Class 4/5 (mutually exclusive features, fragile colouring).** Every spelling that removes the
reload (`Entry* e = t;`, with or without the barrier, with or without a compensating value)
flips the *whole* function's colouring: `key` moves `edi → ebx`, `list` moves `ebx → edi`, and the
loop prologue becomes `lea edi,[ecx+4] / mov eax,edi / test eax,eax` → **ndiff 30** in one step.
9 distinct spellings all produced the identical flip. Keeping the second load keeps the colouring
and leaves exactly the one `mov esi,[eax]` instead of `mov esi,ecx`.

Note the rival draft contains a deliberate hack `if (t == e) n = n->next; else n = n->next;`
(keeps both values live) — **removing it also flips the colouring**, so it is load-bearing for the
`key→edi`/`list→ebx` assignment. That is the shape of a class-5 bracket: the original needs both
"one load, copied" *and* the colouring that only "two loads" produces here.
