### The bisect that localises the trigger (worth knowing)

Truncating the candidate and re-compiling (`out\v4f\tA…u4.cpp`, built by cutting at a line and
closing the open braces):

| version | bytes | first instructions | colouring |
|---|---|---|---|
| up to the land-height compare (no `if (j)`) | 476 | `sub esp,0x34; push ebx; mov ebx,[eax+8]` | eax=apParam, **ebx=source** |
| + `if (j)` body through `ResetSim`/`Update` | 741 | same | same |
| + the `Body* h = apParam->GetBody()` block | 887 | `push ebx; push esi; push edi; mov edi,[ebp+8]; mov eax,[edi+8]` | **edi=apParam**, source spilled |

So the single use `apParam->GetBody()` (plus its `Signal`/`SetFlag4` in the same block) is what tips
`apParam` into a callee-saved register in our build. In ORIG that block **reloads** apParam into
`esi` (`mov esi,[ebp+8]; mov ecx,[esi+0x10]; mov [esp+0x4c],ecx`) and spills `Body*` instead — the
mirror image. Any lever that changes this block's pressure is the place to experiment, not the
parameter list or the declarations.

## Current diff

`out\4f31a0.diff` (551 lines) and `--full-diff` on demand. First differing instruction:

```
ORIG  +0x009 mov eax, dword ptr [ebp + 8]      ORIG +0x00c push ebx
OURS  +0x009 push ebx                          OURS +0x00c mov edi, dword ptr [ebp + 8]
ORIG  +0x00f mov edi, dword ptr [eax + 8]      OURS +0x00f mov eax, dword ptr [edi + 8]
```

**The residue, in one sentence:** ORIG keeps `source` (the `Node*`) in **edi** for the whole
function and reloads the stack parameter `apParam` from `[ebp+8]` (at 0x009, 0x2ec→esi, 0x51f);
our build spills `source` to `[esp+0x4c]` (5 reloads) and uses edi as scratch (apParam's first
range, the constant `1` of the Toggle `or`, the `GetCoordinates` pointer, `current`).
Every other difference follows mechanically:

- `lea eax,[edi+0x8c]` (ORIG) vs `mov eax,[esp+0x4c]; add eax,0x8c` (ours) — this pair is the whole
  3-byte extent excess;
- `world` lands at `[esp+0x4c]` in ORIG but `[esp+0x50]` in ours (source owns +0x4c);
- `push 0; push 0` (ORIG) vs `push edi; push edi` (ours) for `Signal(6,0,0)` in the `!current`
  branch, because our `current` sits in edi and the compiler knows it is 0 there;
- `mov ecx,[esp+0x58]` (coords pointer in a slot) vs `mov edi,eax` (ours).

## Hypotheses / next steps

1. **This looks like residue class 4/1 from `lessons-rival-code.md` §10** — one backend colouring
   choice, insensitive to spelling (17 spellings proved byte-identical here, and the project's
   record elsewhere is 18–40). Class 4 says a stack parameter *always loses* to a local, so ORIG is
   the *natural* outcome and our build is the odd one: look for a **structural** difference that
   lengthens `source`'s live range or adds a real local we do not have, not another spelling.
2. The one shape difference nobody has tried yet: ORIG's first `GetCoordinates()` result lives in a
   **slot**, ours in edi as an unnamed temp. Naming it did not change the .text (copy propagation
   collapses it); forcing a real slot there (e.g. two named uses of the pointer) is the most
   promising remaining lever, because it would occupy edi at exactly the point where our allocator
   uses it as scratch.
3. If that fails after ~30 more minutes: **report `compile_flags`** with the proof table above and
   this candidate (extent 1587, 87 % aligned, one named residue). The build host's solver takes
   close ones from a checkpoint, and the flag proof is worth more to the project than the match.
4. Do **not** re-check this function under the declared /Od set: 500–969 bytes of the neighbours
   move, so any /Od score is meaningless.
