## Hypotheses / next steps
This is **residue class 5** (bracket), not class 1: the compiler will emit `js` only from a mask
source shape and `jl` only from a `< 0` shape, and in *this* function every mask shape also
hoists the zero web (28 forms, invariant — the tail's unsigned compare node re-ranks the zero,
not a spelling question). Not a scratch-count dial issue and not a liveness issue.

Levers left, in priority order:
1. A source shape where the flag test is a mask but the *first* zero use stays after the
   `Insert` call — the hoist is global, so the trigger has to be upstream of the tail. Try
   changing what produces the *tested value* rather than the test: e.g. read the capacity into
   an `int` **through the same pointer expression the loop uses**, or test the field of the
   struct via a reference taken in the loop body's scope.
2. Look for a *sibling* in the image using the same idiom at the same size (the pack's
   `~Array38`, unit line 2099, and `FUN_00901f10`, line 10118) and check whether the already
   verified neighbours with the mask emit js **without** the hoist — if one does, copy its
   exact containment shape.
3. Build-host solver: the 243/1 draft is a genuine one-opcode near miss, worth its longer search.
