* This is the same failure mode as lessons 19.2 (`volatile` stores can be **merged** at a join) and 19.15

## Verdict
**Proved class 2 / store-scheduling wall.** With ~10 instructions and 120 permutations covering the legal
orderings, there is essentially no unexplored source space left. Do not re-claim this expecting a spelling to
fix it; it needs a compiler-behaviour discovery, not more variants.

## If someone does reopen it
Try, in this order (none of these were run):
1. Make one of the two const stores go through a **different address expression** (e.g. an accessor rather
   than a member write) so it is no longer a const store the scheduler can reorder around.
2. Give `[eax+8]` an **aliasing partner** - a second named reference to the same field - so the store cannot
   be treated as dead-store-mergeable.
3. Change the **type width** of the `[eax+0x10]` store so its cost differs.
