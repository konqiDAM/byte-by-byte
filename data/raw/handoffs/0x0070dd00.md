## Classification

**Class 2 / class 5 hybrid — a per-block C2 restore-list tie-break.** Identical instruction set,
identical widths, identical slots, identical live ranges; only the emission order of two
independent restores differs (one 2-instruction permutation = 2 aligned diffs). Nothing in the
diff can be attributed to a source shape; the two values' definitions, first uses, last uses,
spill slots and register numbers are all fixed by bytes that already match.

Direction is worth recording, because it kills the "the image always restores descending"
theory: here the image is `ebx`(3) then `esi`(6) = *descending slot (`0x2c`,`0x24`) / ascending
register number*, exactly like `0x008899e0` (`ebp` then `esi`). Our build emits ascending slot /
descending register number in both functions. Three instances of this residue in the corpus
(`0x0070dd00`, `0x008899e0`, `0x00927640`) and no source spelling has ever moved it.

## Diagnostic facts worth keeping

* `if (0) vp = &form;` is a **no-op for `form` in this function**: `form` is a stack parameter, so
  it already has a home. (The trick works in `0x00927640` because that parameter had *no* home.)
  It costs nothing and changes nothing here — do not spend another session on it.
* Inserting the trick for `biped`/`d` *does* perturb the allocator (length changes) → the trick
  is live, it just cannot choose the target order.
* `form` is reloaded from the **argument home**, `biped` from a **real spill slot**; the target
  emits the *argument* reload first. That is the one asymmetry a future solver could exploit:
  make `biped`'s restore an argument-home reload too — impossible from source, since the argument
  home is fixed by the ABI and the slots already match byte for byte.
