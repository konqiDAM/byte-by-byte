## What did not work (36 variants, measured)
1. **Bind the value once** (`unsigned v = *(const unsigned*)s; *d = v; if (swap) *d = _byteswap_ulong(v);`)
   → **extent 347**, ndiff 6: MSVC coalesces the load and the `bswap` into one register
   (`bswap eax` in place) and the two-byte `mov` disappears at each site. Same for: `unsigned w = v;`,
   const-ref bswap helper, identity ternary `v==v?v:v` as the bswap operand, struct temporary holding
   the value, `(unsigned long)` cast, `Sw(&w)` on a copy, ternary with two identical side-effect arms,
   `if (swap && v==v)`, `__forceinline unsigned Bsw(unsigned v)` / `void St(unsigned*,unsigned)` (value
   parameters), and the value returned by the helper with the result discarded. All → 347.
2. **Make the value live with a zero-cost use** (`s += 4 + (v & 0)`, `v = v;`, `(void)(v == v)`) → folded
   before the register allocator, still 347.
3. **Helper returns the value and the caller stores it** (`navID = Rd(&navID, src, file);`) → **the copy
   finally appears** (`mov edx, eax; bswap edx`) but each site also gains a third `mov [esi], eax`
   → extent 359. The copy is real, the extra store is not in the original.
4. Reload-into-a-named-pointer (`unsigned v = *p; ... _byteswap_ulong(*p)`) → still reloads (the store
   between the two loads blocks CSE by aliasing) → 353/3, same as the current best.

## The codegen law (measured with VS2005 SP1, files kept in `exp91/bs/bs*.cpp|asm`)
A discarded-return `__forceinline` helper always coalesces the bswap into the value's register
(`bswap reg` in place). VS2005 emits `mov r2, r1; bswap r2` **only when the value r1 is still live
after the bswap** — verified with `unsigned f(…){ …; if(b) *d=_byteswap_ulong(v); return v; }`
(f7 in `bs2.asm`) and with the caller-stores-the-return case above. So the original's third `mov` per
site means **the loaded value has a real later use inside the original source** that costs no
instruction. That is the whole remaining gap: find a zero-instruction live use (or a use the encoder
folds into the existing `push esi` / `push eax` sequence at the call sites).
