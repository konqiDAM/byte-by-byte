## THE MECHANISM (this is the new result - the wall is not a liveness rule)

From the slot maps of all 78 candidates:

1. A 12-byte object created at statement S gets **the highest 12-byte slot whose live range does not
   overlap S**, and **the next object created in the same statement gets the next slot *down***.
   The walk is **monotone downward and never restarts at the top of the frame**.
   * base: inner sret -> `displacement`(-0x18) = highest free (because `snapshot`(-0xc) is live),
     outer sret -> -0x24 (next one down) = `cameraPoint`.
   * `inner_named` (`Point scaled=FUN_00468cd0(...); selected=unk218.FUN_00422970(scaled);`):
     `_scaled` -> -0x18, outer sret -> -0x24. **-0xc is provably free at that second statement
     (`snapshot`'s last use was the statement before) and the walk still does not go back up to it.**
     That kills the "most-recently-dead / highest-free" hypothesis outright.
   * `pod_point` (no `Point` ctors): three temps at -0x18, -0x24, -0x30 - strictly downward.
   * `a_writeback_two` (frame grew 12 B, `displacement` ends up at -0xc): the temps are -0xc and
     -0x18, i.e. the walk still starts at the highest 12-byte slot and goes down.

2. So the **only** thing that differs in ORIG is that slot **-0xc (`snapshot`) was free when the
   *first* 12-byte object of that statement was allocated** - and ORIG's first such object is the
   **outer** return buffer (its pair is {outer -0xc, inner -0x18}, i.e. up-to-down, while every
   build we can produce is {inner -0x18, outer -0x24}, down-to-down). In ORIG the hidden return
   buffer of `FUN_00422970` was allocated **before** the argument expression was walked, so the
   forward-pass liveness still had `snapshot` dead (its last recorded use was the
   `FUN_00475250` call one line earlier); in our build it is allocated after the arguments, so
   `snapshot` counts as live for the whole statement.

3. **The last-use lever of the brief is therefore disproven, with direct evidence.** `snapshot`'s
   final read IS already the last instruction before the buffer's `lea` (`lea edx,[snapshot];
   push edx` at +0x220/+0x224, buffer `lea` at +0x226), and it changes nothing - because the
   allocator's reservation is per *statement*, not per last-read position. Making `snapshot`
   unambiguously dead for a whole statement (`inner_named`) does not move it either.

4. Consequence: **no source spelling can select the slot.** The choice is made by the front end's
   expression walk (buffer-before-arguments vs after), which C++ text does not control. The frame
   map is fixed (5 12-byte slots at -0xc/-0x18/-0x24/-0x30/-0x3c, 3 dwords of scratch at
   -0x40/-0x44/-0x48, `sub esp,0x48` exactly full), so there is no spare slot to shift the walk
   into and no way to place a 12-byte object above `snapshot`.

### Also confirmed negative (do not re-derive)

* Assigning the result back into `snapshot` (which would *force* the buffer onto its slot by
  source semantics) costs 8 bytes: MSVC uses a temp and then copies into `snapshot`
  (1716 vs 1708). ORIG's post-call sequence is 3 movs from `[eax]` straight into `selected`, so
  ORIG really did assign to a *different* object and only the allocator chose `snapshot`'s slot.
* `Point projected = <call>;` makes MSVC pass `&projected` directly with **no** temp - 1697 B,
  84 diffs. So ORIG is not that shape either.
* Named locals get their slot at the declaration point in the same walk (after the arguments), so
  naming the destination cannot pre-empt -0xc.

## Verdict

This is a **class-3 compiler tie-break** (the same class as 0x0073e740 / 0x007641c0, lessons 9.1b),
not a source shape. 78 measured candidates across 12 structural families, 0 movement. Recommendation
for the other two siblings: stop searching source shapes for the sret slot and record the
downward-walk rule instead; the remaining lever is the build host's solver, so keep releasing with
this draft (it is the closest possible: one 4-byte `lea` displacement).

If anyone wants one more shot, the only untried idea consistent with the mechanism is a sibling
function in the same unit that takes a `Point`-returning call as an argument **after** a named
12-byte local has died, to see whether SP1 ever allocates a return buffer before its arguments.
The pack's unit (`unit_3a393c80f78f.cpp`) can be compiled and grepped for
`lea reg,[esp+X]` followed by `push reg` + `call` with X higher than the neighbouring temp's.
