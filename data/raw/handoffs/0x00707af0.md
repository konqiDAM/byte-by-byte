## Hypotheses / next steps
One decision: **our build knows `ebx` (`style`, zeroed by `xor ebx,ebx` at +0x0b4) holds 0 and uses it
as the zero operand of the compare; the original's compiler does not.** Confirmed by experiment:
making `style` uninitialised (`int stance=0, style;`) makes all three compares match exactly — but it
also frees `ebx`, so `equipment` takes `ebx` instead of the frame slot and `lea ebp,[ebx+2]` becomes
`mov ebp,2`; net 556 bytes, 103 rows. So the target shape needs **`ebx` occupied by `style` AND
`style` not provably 0 at +0x100..+0x12b** — i.e. the original's `style = 0` def is *after* the
compare region in source order and the scheduler hoisted `xor ebx,ebx` up into the `item()` call's
shadow while the "use a known-zero register" peephole had already run. A plain assignment
(`style = 0;` on the fall-through only, legal to `goto` over) reproduces the compare forms but loses
the hoist, so `ebx` stays free.

Concrete things left to try: (a) a shape where the `style = 0` def is after the compares but `ebx` is
still live across `controller->item()` (e.g. an extra use of `style` in the mask chain that ORIG also
has — ORIG's chain only writes `ebp`, so this is probably closed); (b) a `/Os`-style flag set — the
register form is a *size* optimisation, so check whether this one function matches under
`/MT /O1 /GS /EHsc /Gy` (not in `accept_also`, so it would need a `compile_flags` report with a
matching checkpoint, per agents.md step 7); (c) the project's long permuter on this file.

### What this function's ORIG actually is

Our build: nz_reg 3, nz_imm 5 (shares `ebx`). ORIG: the three residue compares become
immediates, i.e. **nz_reg 0, nz_imm 8** - a pure immediate-style function. Our build is one
hoisted zero away from it, and every byte outside those three instructions already agrees.

### Synthesis: this is the colouring tie family, and it breaks BOTH ways

- here: **ORIG does not share** a zero (`al` + immediates), ours shares one in `ebx`;
- `0x008e4d50`: **ORIG does share** one zero in `ebx` across four webs, ours puts it in `edi`
  and spills `e4`/`key`/`pair` (frame 0x40 vs 0x3c).

Same family, opposite directions. That is lessons 19.83 (a run of register ties is ONE cycle
rotated by a slot) rather than a pressure threshold, and it means the fix is a *whole-function
colouring* change, not a local one. The two measurable handles for the next agent are
`zeroreg_corpus.py`'s live set and `zeroreg_webs.py`'s nz_reg/nz_imm - run them on any candidate
to see which side of the tie it fell on.
