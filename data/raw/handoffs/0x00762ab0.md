## Mechanism, measured (toys `%TEMP%\opencode\sw8..sw13.cpp`)
For a 2-case `switch` on a value that ends in a callee-saved register:
* copy emitted (`mov eax,<r>; sub eax,0`) when the function has **≤3 callee-saved values live at the
  dispatch** and **no value live across the calls before the value's definition** (`sw6.cpp` f1, `sw9.cpp`
  b0/b7/L3C2, `sw13.cpp` x1/x5);
* temp coalesced into the switch value (no copy) with **4 live callee-saved values** (`c1`, `L4C2`) or any
  earlier live-across-call value (`x4`, `x6`, `x7`) — that is our function's camp;
* a switch value **in memory** copies as `mov eax,[esp+X]` (3-4 bytes, not the target) — `b4/b5`, `f2_data`;
* EH frames/managed objects do not block the copy by themselves (`t1`, `e4` copy).
`x1` vs `x4` (`sw13.cpp`) is a minimal pair with an *identical* live set at the dispatch; only the earlier
value history differs and the copy flips. So the lever is a global value-graph difference, not the dispatch.

## Corpus mining (new)
Only **17** sites in the whole 9.9 MB .text contain `mov eax,<r>; sub eax,0`; ours is one (`+0x16b`). In every
other sampled site the copied value is either **live after the switch** (usually loop-carried: 0x0044fb70,
0x0058c9d0) or a **constant / stack-loaded** value (0x0078db00, 0x005969d0). None of the 16 is a matched
corpus function, so there is no source template to copy. A *genuine* live-after use of k in our function
(`swD.py`) does **not** give `mov eax,ebx`: it re-allocates everything (k spills, ebx becomes a zero temp) and
the chain changes shape. "Make k live" is therefore not a usable lever.
