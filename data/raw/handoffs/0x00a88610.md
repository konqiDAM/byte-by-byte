## The lever that took it from 307 bytes to 23 (new, measured)

The array constructor. With a member-init list

```cpp
__forceinline F3Array() throw() : m_data(0), m_iElementCount(0), m_iCapacityState(0x80000000) {}
```

the constant 0 is **one web from the ctor (+0x2dd) across four calls to the compares**, so it needs
a callee-saved register and takes `edi`; the saved stream pointer is then spilled to a stack slot
(one extra `mov` at +0x2c4) and both compares use `edi`/`di` instead of the immediate 0 — **307
bytes differ**. Written the way the pack's own `MyArray` is written,

```cpp
__forceinline F3Array() throw() { memset(this, 0, 8); m_iCapacityState = 0x80000000; }
```

VC8 emits the ctor's two zeros as two *immediate* dword stores, the zero web never spans a call,
the spill disappears, both compares become `cmp [x],0`, and the residue falls **307 → 23 in one
edit**. Same family as SESSION_CLOSE_7 lever 1 (one value in the wrong place re-colours
everything) but the trigger is a constructor's zero rather than a redundant copy: if a big
function's tail spills a pointer and uses a callee-saved register for a constant, try
`memset(this,0,N)` for the zero.
