## Why it works - the general lesson

The gap was never the store; it was the `mov eax,ecx`.  Every spelling that only **writes**
through `this` lets VC8 fold the pointer into the addressing mode (`mov dword ptr [ecx],imm32`,
7 bytes) - ~30 spellings were measured (store through `this`, through a member slot, through a
union, through `char*`/`unsigned short*` casts, volatile members and locals, and inlined helpers
taking the pointer by value, by reference and as volatile).

`mov eax,ecx` only appears when the value of `this` itself has to exist in **eax** - i.e. when the
function **returns the pointer, or a reference to the pointed-to slot**.  The reference return
forces MSVC to materialise the slot's address (= `this`) into eax, the return register, and the
store then goes through eax.

**So the original is a reference-returning setter/accessor, not a void setter.**

Three fallbacks that also produce the exact bytes (verified by the sub-agent, `exp91/ax30/`):
`void*& r = *(void**)this; r = &D; return r;` - `void*& r = vptr; r = &D; return r;` -
`void** p = (void**)this; *p = &D; return p;`

**Generalisable rule: when VC8 folds a value into an addressing mode and the original did not,
look for a SECOND USE of that value in the source** - a return value, a reference, a second read.
That is usually what forces the register copy the original has.

**The whole family**: every `mov eax,ecx / mov [eax],imm32 / ret` in the image is now a quick
match - see `exp91/vtables.json` (built by `exp91/gen_vtable.py`).
