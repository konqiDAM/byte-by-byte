## What worked

Not a single source change moved the score, but the **mechanism is now measured**, which is the
new result of this session (the previous give-up only guessed at "web cost").

1. Fast local oracle built and verified against the real bytes:
   `python out\00a89680\oracle.py check <file.cpp>` compiles the body standalone with
   `win_tools\msvc9.py /O2 /MT /GS /EHsc /Gy` (0.4 s, no checker, no API) and compares the
   `.text` bytes with the original 435 extracted from the image. Same result as
   `exp91\score_pack.py` (0.4 s vs 84 s) - this is what makes a 100+ sweep affordable.
2. **The residue is a cost race that we lose by less than one loop use.** Adding one *real*
   use of `this` inside the loop body flips the whole prologue to the target shape:

   ```cpp
   int quadrant = 0;
   if (((QuadCallStandIn*)this) == 0) quadrant = 9;   // diagnostic only, +13 bytes
   ```
   → `sub esp,0x1c / push ebx / push ebp / mov ebp,[esp+0x2c] / push esi / mov esi,ecx / push edi`
   = the original prologue, byte for byte (`out\00a89680\b2.py`, `b4.py`).
3. The flip is specific to **`this` in the loop body**, not to a bigger block:
   - a use of `this` **before** the loop (preheader) → no flip;
   - a use of `this` **after** the loop → no flip;
   - adding a *different* value to the loop-head block (`counter`, `p3`) → no flip.
   So cost(this) is just under cost(center), and only a use in the loop closes the gap.
