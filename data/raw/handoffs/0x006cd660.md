## Current diff (the whole remainder)
```
ORIG 001e  movzx edx, word ptr [esp + 8]   |  YOURS movzx eax, word ptr [esp + 8]
     0023  mov ecx, dword ptr [esp + 4]   |        (same)
ORIG 0027  mov ax, dx                      |  YOURS movzx edx, ax
     002a  mov dword ptr [esp + 0xc], edx |        (same)
     002e  mov word ptr [ecx], ax         |        (same)
     0031  ret                            |        (same)
```
Both variants are 20 bytes for the arm. The original keeps the **zero-extended 16-bit value in EDX** and
copies its low half into **AX** (`mov ax, dx`, 3 bytes); we keep the value in **EAX** and re-widen for the
volatile `size` store (`movzx edx, ax`, also 3 bytes). So the byte count can never separate the two: this
is a pure **register-colouring flip**, not a shape or size problem.

Target requirement: `cost(h) > cost(w)` so the narrow value (`h`, the return value) is coloured first and
takes EAX, forcing the wide value (`w`) into EDX and producing the copy. In our sources the trunc
`h = (unsigned short)w` also counts as a **use of w**, so the costs tie (2 vs 2) and the tie-break
("full ties go to the value referenced first in the source") gives EAX to `w` — which is declared first.

## What worked
- **Dropping `volatile` from the 16-bit read** (`*(unsigned short*)&value`, no volatile) turned the draft's
  `mov dx, …` + `movzx eax, dx` (ndiff 3) into `movzx eax, …` + `movzx edx, ax` (ndiff **2**). Confirmed.
- Keeping one named 16-bit local used by both the `size` store and the `*(unsigned short*)output` store is
  what makes the arm come out at exactly 61 bytes with 0 errors.
- `size = h` (16-bit value into the volatile slot) is the form that keeps the 61-byte extent with the
  `movzx` load. `size = w` (plain 32-bit store) shortens the arm to 58 bytes (the compiler drops the
  widening and puts the output pointer in EDX) — that variant can never match.
- Fast tooling used: `exp91\score_pack.py` (rank), `exp91\scan6.py` (dumps only the 0x1e..0x31 window),
  `exp91\g6cd660*.py` rounds 1–6 (~800 variants, one compile each, 6–8 threads, ~40 s/round).

## What did not work (each measured, extent/ndiff)
1. Two source reads of the same 16-bit slot (any order, any base indirection via `unsigned char*`/`void*`):
   MSVC merges them and picks the **cheapest encoding** — `mov eax, dword ptr [esp+8]` + `movzx edx, ax`
   = 6 bytes, extent **60**, ndiff 6. It is byte-optimal for that source; the original is 2 bytes longer,
   so the original is *not* two reads of one slot.
2. `unsigned int w = *(unsigned short*)&value; size = w; …` with any arrangement of the word store and
   return: the trunc aliases w's register (sub-register alias, free) → arm collapses to **58** bytes.
3. Retyping the second parameter so the 16-bit object is 2 bytes (`unsigned short value`, and a
   `struct V { unsigned short lo, hi; }` by value): the promotion still happens for the two-read shapes
   (60 bytes), single-read shapes still give 58. Parameter retyping does not unlock it.
4. `volatile` on the 16-bit read (either direction), `volatile` on the word store, `*(volatile unsigned int*)&size = w`,
   identity ops to raise `h`'s IR use count (`h & 0xff`, `h | 0`, `h * 1`, `h ^ 0`, `h - 0`,
   `(unsigned char)*(unsigned char*)&h`), `(unsigned short)(w & 0xffff)`, statement reordering
   (size-store first / word-store first), named pointer locals, `return *(unsigned short*)output = h;`:
   no change in the residue, or worse (58/60/69/75 bytes).
5. `h == … ? w : w` identity ternary: adds a `test`/`cmp` (69 bytes) — no free use available here (there is
   no existing comparison in this arm to piggyback on).

## Hypotheses / next steps (priority order)
1. **Find a free third use of `h`**, or remove the trunc's use edge from `w`, so the cost tie breaks for `h`.
   The arm itself has none; consider a shape where `h` is also the operand of the `size` store *and* w's
   store is not a use of w (e.g. `size = *(unsigned short*)&value` where the load is folded into EDX
   without a source variable) — that was round 4 (Z1–Z6) and it promoted the load to a dword read.
2. **Force the sub-register alias to fail.** The alias `h = low16(eax)` is free, which is why the compiler
   prefers it; anything that makes AX unavailable at `h`'s definition (a live value on EAX whose live range
   crosses 0027..002e, at zero instruction cost) should force `mov ax, dx`. No such zero-cost value was
   found in this 20-instruction arm.
3. Search the image for a **proven twin** of this idiom (`movzx r32, word ptr [esp+N]` followed by
   `mov ax, dx` + a 32-bit store of the same value, plus a 16-bit store) — a matched neighbour with a known
   source would settle the idiom. The function is a "write N-byte value / report width" helper; its
   callers are around 0x006cd6xx.
4. If SP1 truly cannot produce this colouring, the site's longer solver on `best_code` may finish it —
   submit the ndiff-2 source as the checkpoint code rather than the ndiff-3 draft.
