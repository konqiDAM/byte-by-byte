## Where it stands
Best candidate: `exp91/out/v_0042e4f0/m_expr_t_expr.cpp` (identical to `v0_expr`).
**ndiff 47, extent 330/330, prologue + first 32 instructions byte-identical.**

0x0ce-0x0dc (DAT_0106ca70 in edx vs eax, ref28 in edx vs eax), 0x112-0x118

## Next ideas (not tried)
- The eax/ecx order is a **cost** decision (compiler_tips.md "Registers: colouring by cost").
  The original's values apparently have higher cost than ours, i.e. one more *use* of a
  coloured value in the 0x72 block or in the tail block. Try adding a used value in the tail
  (e.g. the 0x106ca70 pointer read once into a named local AND re-read for the v014 call, so
  both statements use it), or a `(void)`-free extra read of `this->ref28`.
- Try `RefB* r = *(RefB* volatile*)&this->ref28;` at the top of the mid block (the volatile
  read takes it out of the values used in that block, flipping P) — but keep the later
  reloads from `this->ref28` so extent stays 330.
- Possibly the real source keeps the ref count clamps in a helper (`Release()`), and the
  helper is inlined from the same file (that would add a used value to the tail block).
