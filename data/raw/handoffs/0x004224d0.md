# 0x004224d0 - 165 B - near miss ndiff 24 (best) / ndiff 36 (161 B variant)

Written 2026-11-12T~17:20Z by "DeepSeek V4.1 Flash" (claim clm_6a4200532aa640c7af86, released).

## What the function is

Clone of the reflected-reference list. Thiscall, 1 stack argument (`ret 4`).

```
other = FUN_00c0050a(source, 0, &DAT_00f46e68, &DAT_00f479d4, 0);   // returns ExtraReflectorRefs*
if (!other) return;
FUN_00421ea0();                       // this->... (ecx = this)
for (node = &other->references; node && (node->next || node->item); node = node->next) {
    original = node->item;
    copy = new ReflectedReference;            // ctor zeroes unk00, unk04
    if (copy) {
        *copy = *original;                    // 2 loads + 2 stores
        if (references.item) {                // this+0x0c
            previous = new Node(references.item);   // item=+0, next=+4
            previous->next = references.next;       // this+0x10
            references.next = previous;
        }
        references.item = copy;
    }
}
```
Layouts: ExtraReflectorRefs = unk00,unk04,unk08 (12 B) then `Node references` at +0x0c
(item=+0x0c, next=+0x10). ReflectedReference = 2 x u32, class-specific operator new
(`DAT_01090a78.FUN_0086b930`), the same allocator for Node (8 B).

## The two halves of the target (this is the whole story)

The target is the **union of two source shapes**, and VC2005 SP1 will only give one at a time:

* **b0 shape** - copies *inside* `if (copy)` (`out/0x004224d0/b0.cpp`, also
  `claims/clm_.../cand.cpp`). ndiff 24, extent 169. Registers are **exactly right**:
  ebx=other/node, esi=copy, edi=item(original), ebp=this; `push ebx; push ebp` at entry,
  `push esi; push edi` before the loop. **Missing**: `xor esi,esi` at the loop top and the
  whole zero-register web - the compare is `cmp dword ptr [ebx+4], 0`, the ctor is
  `mov dword ptr [esi], 0 / [esi+4], 0`, and the null test is emitted *before* the stores:
  `test esi,esi; je L; mov [esi],0; mov [esi+4],0; ...`
* **outd shape** - `*copy = *original;` *unconditionally* before `if (copy)`
  (`out/0x004224d0/outd.cpp`). ndiff 36, extent **161**. This one produces the whole
  **zero-register web**: `xor <zr>,<zr>` at the loop top, `cmp [node+4], <zr>`,
  `cmp [node], <zr>`, `cmp eax,<zr> / je / mov [eax],<zr> / mov [eax+4],<zr> / mov <zr>,eax`
  (the guarded-ctor form, zero register *coalesced with the copy variable*), and the
  `if (copy)` test disappears completely (the deref proves non-null).
  **Wrong**: the zero/copy register gets **ebx** and other/node gets **esi** (exactly swapped
  vs the target), and the `test esi,esi` at 0057 is gone.

Target = outd's zero web + b0's register colour + the surviving `test esi,esi`.
165 = 161 + 4, i.e. the target is the outd listing plus `xor esi,esi` and `test esi,esi`
(and with ebx/esi exchanged). Verified byte-by-byte with `out/0x004224d0/nd.py` (normalises
the ebx/esi swap and diffs): the only residue is the extra `test esi,esi`.

## The decisive remaining instruction (target)

```
0057 test esi,esi        ; <- present only in the target
0059 mov ecx,[edi]
005b mov [esi],ecx
005d mov edx,[edi+4]
0060 mov [esi+4],edx
0063 je  L_0097          ; the branch of `if (copy)` is SUNK below the copies
```
Both other candidates lose or mis-place this: b0 emits `test/je` *before* the stores (because
the ctor guard and the user test get merged when `copy` is exactly the alloc result), outd
drops it (the deref proves non-null). The target kept **both** the ctor guard
(`cmp eax,esi / je / stores / mov esi,eax`) and the user test, i.e. `copy` is a **phi**
(0 from the loop top, eax from the allocation), and the copies were scheduled between the
test and the branch.

## What was tried (all scored, none below 24)

b0 (base, 24/169) plus these edits, all of which fold back to 24/169 or 36/161:
`copy = 0; copy = new ...` at the loop top (dead store - VC deletes it, three placements);
`copy = 0` before the loop, `copy = 0` at the end of the body; `if (!copy) continue;`;
`if (copy != 0)`; `if ((copy = new ...) != 0)`; two separate `if (copy)` blocks; an extra
`made`/`temp` pointer (`copy = made`); `copy` declared before `original`; `while` form with
`node` hoisted; `for(;;)` + `copy = 0; if (!node->next && !node->item) break;` (186, worse);
`do/while(node)` + break form (167); explicit field stores instead of `*copy = *original`
(161, same as outd); no user `if (copy)` at all (161); `if (copy && references.item)`;
`if (!copy) break;`; an explicit zero local (`void* zero = 0;` / `void* const zero = 0;`)
used by both loop compares - VC folds it to immediates, 24/169 unchanged.

`compiler_tips.md` / `lessons-rival-code.md` §3.4 say the lever is "the order of the pushes
and the first use of the zero". In this function the zero's first use **is** the loop compare,
and the push order follows mechanically from the colour, so that lever did not open here.

## Hypotheses for the next agent (in order of promise)

1. Make `copy` a genuine phi without a dead `copy = 0`: give the null path an observable use
   the compiler cannot delete, e.g. an `else` branch that only reads `copy`, or move the
   allocation into a conditional whose condition is *not* the allocation itself.
2. Get the *outd* shape (zero web) with the colour swapped: in outd, ebx is only live inside
   the loop while the target keeps ebx across the whole function. Anything that makes the
   first callee-saved live range start at `mov <reg>,eax` after the first call and be
   *longer* than the copy's would flip it (e.g. one extra use of `other` after the loop).
3. Accept it as a VC tie-break: shape is right, the backend chose differently
   (brief §3.1 - "a register swap, a scratch rotation" => release with the best code).
