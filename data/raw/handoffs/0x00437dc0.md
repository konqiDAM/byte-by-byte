## What worked

1. **`state->scratch` needs a named local** — original `0x02c1` is
   `mov eax,[eax+0x1e0]` + `lea ecx,[eax+0x30]`; spelling it
   `DAT_0116efb8->unk1e0->scratch.FUN_00abb340()` gives `mov ecx,[eax+0x1e0]` + `add ecx,0x30`.
   Using `State* state=DAT_0116efb8->unk1e0; state->scratch.FUN_00abb340();` (and `state->count`,
   `state->candidates` later) removed 2 instructions of residue — this is the only change I kept
   on top of the packet's best draft.
2. The draft's `Pop(RefLink*&, Ref*&)` / `Pop(GroupLink*&, GroupData*&)` idiom, **taking the
   reference**, is by far the closest loop scaffolding (see the table). Its `if(!p){p=0;return false;}`
   produces the original's "zero the carried value, jump to the latch" exits:
   ORIG `0x01b6 test eax,eax / je L_050f` where `L_050f = xor edi,edi; jmp L_021c` (inner loop) and
   `0x01a2 je L_0508` where `L_0508 = xor ebp,ebp; jmp L_0222` (outer loop).
3. Load order inside `Pop` must be **next (offset 0) first, then value/data (offset 8)**:
   ORIG `0x01bc mov edi,[eax] ; 0x01be mov eax,[eax+8]`. Reversing it costs ~25 % of the function
   (see table) — do not "tidy" it.
4. `IsTarget()` as a `__forceinline` member that reads `unka0[0]` twice (once for the null test /
   virtual call, once for the argument) is **exactly right** — both bodies are byte-exact, including
   `sete al / test al,al`.
5. Collector layout confirmed from the code (keep it): `source` at `+0xc`, `planes[6]` at `+0x2c`,
   object at `[E+0x40]`; `FUN_00ae2490(this=manager, Scene*, Vec by value, &collector)` and
   `FUN_00ae4660(this=manager, Scene*, collector+0xc, collector+0x2c, bool)`.

## Current diff — the five real gaps

1. **Group loops `0x0190-0x02af` (70 lines).** The draft's `Pop(GroupLink*&)` makes `outer` (and
   `data`) **memory-homed**: ours does `mov ebx,[eax+0x3c]` and `mov [esp+0x24],ecx / mov ebx,ecx`
   where the original keeps `outer` in **eax**, `data` in **edx**, `next(outer)` in **ebp**,
   `next(link)` in **edi** with *no* stack slot. Consequence: the original's loop-exit goes
   `je L_0508` (`xor ebp,ebp; jmp 0x0222`) / `je L_050f` (`xor edi,edi; jmp 0x021c`); ours goes
   straight to the exit label and its outer latch tests memory (`cmp dword [esp+0x24],0`).
   This is the first real difference in the function (first mismatch after `0x091`) — fix this first.
2. **`0x02df mov ebx,[FUN_00d9b068]`** — the original hoists the `__imp_InterlockedIncrement`
   thunk into **ebx** once and calls `call ebx` at `0x02ef`, `0x059f`, `0x05ff` (i.e. LICM out of
   the candidate loop, 0x556-0x5a6). `__imp_InterlockedDecrement` (`0xd9b064`, uses at 0x3ad/0x5e1/
   0x611, none inside a loop) is *not* hoisted in the original either. Ours calls
   `call dword ptr [0xd9b068]` everywhere and instead hoists `manager` into ebx at `0x0541`.
   Note the original's register order in the tail follows from this: `state`=**ebp**,
   `current`=**edi** (`0x05cc mov ebp,[eax+0x1e0]; 0x05d2 mov edi,[ebp+0x2c]`), while ours is
   `state`=edi + `add edi,0x2c`, `current`=ebp. Fixing the ebx conflict probably fixes 0x2c0/0x500/
   0x580/0x5c0 windows (≈40 lines) at once.
3. **Slot pair swapped: `0x24` vs `0x28`.** Original: `selected` at `[esp+0x28]` (spilled `0x02e5`)
   and the `y' = position.y*scale` x87 temp at `[esp+0x24]` (`0x033c`), then the grid loop reuses
   `[0x28]` for `x` and `[0x24]` for `y`. Ours is the mirror: `selected`/`x` at `0x24`, `y'`/`y` at
   `0x28`. This single swap costs the x87 block (`0x324-0x386`, 6 lines) **and** the whole grid loop
   (`0x3ef-0x503`, ~10 lines: `0x03ef`, `0x03fb`, `0x04ef`, `0x04f7`, `0x04e5`). Tested: declaring
   `Vec query;` before `Strong<Scene> selected` makes it worse (extent 1628, pairs crash) — the
   allocator gives later-declared locals the *higher* offset, so the original must have had
   something live in `0x24` at `0x02e5` that we do not. Worth trying: a function-scope `y`/grid
   counter declared *before* `selected` (the original's counters are **memory-resident** —
   `add dword [esp+0x24],1` at `0x04e5`, counters reloaded from memory at the latch — so the source
   likely took their address or they are members of a local struct).
4. **x87 order `0x0324-0x0332` (wall candidate).** Original: `fld [px]; fld [s]; fld st(0);
   fmulp st(2); fxch st(1); fstp [0x14]`, ours: `fld [s]; fld st(0); fmul [px]; fstp [0x14]`.
   Same for `+`: original `fld [x']; fadd [eax+0x8c]`, ours `fld [eax+0x8c]; fadd [x']`.
   All 4 commutative-order source spellings test byte-identical, so this looks like the
   `compiler_tips.md` "x87 rank is not reachable from source" class.
5. **`0x038a` / `0x03a3` scheduling and `0x05c8-0x0622` tail** — conditional jumps to different
   labels and the `state`/`current` colouring of item 2; the original also schedules
   `test esi,esi` at `0x02f1` (consumed by `je L_0533` at `0x038a`), ours puts it at `0x02ef`.

Frame facts worth keeping: `E+0x14` = `this` early then `bool first` (`mov byte [0x14],1` at
`0x0535`), `E+0x18/1c/20` = `position` and later the query base (`input->unk68/74/80`),
