## Residue class: 2 (one instruction in a different position; eax availability / scheduling tie)
The int `add` and the x87 `fstp` are independent. SP1's list scheduler keeps the `add` tied to the
`out->f40` store (it lands at 0042, right before the store at 0045) and lets only the *load* float up
into the `fld`→`fstp` shadow. In the original the `add` floated too, i.e. its value was *not* tied to
the store — but every spelling that separates the add from the store (named `q`, two statements, `q`
before the last copy) gets **copy-propagated back** into the store, reproducing our schedule.

## What I would try next
The mechanism is `compiler_tips` §"One instruction out of place": *"a load and the store of the same
statement move together"*. Everything that makes the add a separate value is propagated away, and
everything that keeps it separate (mid position) forces `ecx` + an early store. Untried ideas:
1. a value with a genuine **second use** whose second use costs zero bytes (none exists in this
   function — that is the blocker);
2. a **parametric accessor** (`T* Get(unsigned off)`) for the `in->unk08` read so the add becomes part
   of an address tree rather than a statement value;
3. an inlined helper *taking* the pointer (`out->Set40(in->unk08 + 0x50)`) so the store's value node is
   created at the call site, before the last copy;
4. if 1-3 fail, this is a scheduler tie no C++ text reaches → **give up with `instruction_order`** and
   let the build host's solver take the near miss (219/2 is a perfect solver input).
