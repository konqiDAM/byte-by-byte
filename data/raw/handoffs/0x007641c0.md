## Hypotheses / next steps
The blocker is a *frame-layout* rule for the aggregate-return temporary, not a code-shape rule. In the original the
temporary occupies its 12 bytes of frame space (the frame sum proves the symbol is 12 bytes) but is *placed* 8 bytes
higher than a plain contiguous pack would put it, leaving 0x08..0x0f free. Possible causes, in priority order:

1. **c2 aligns this return buffer to 16** (0x10 is 16-aligned, 0x14 is not). If so, some property of the *return
   type* (not `__declspec(align)`, which also aligns the stack) makes c2 treat the aggregate as vector-like. Try
   types that change its "aggregate class" without changing size: a type with a user copy constructor/assignment
   only (the previous contributor tried a copy ctor: unchanged), a `union`, a struct whose last member is a
   `__m128`-sized union member that is never used, `struct { float x, y, z; __declspec(align(16)) };`, or declaring
   the type with `#pragma pack` variants. Watch the frame map: what is needed is `$T` at 0x10 with size 12 and the
   frame still 0x150, with no `and esp` in the prologue.
2. **A second, invisible 8-byte symbol** at 0x08 (c2 sometimes keeps a slot for a front-end temp it optimises away).
   Every source-visible local that is unused is dropped, so this would have to be a compiler temp (a `$T`/`tv`).
   Try source forms that create extra front-end temporaries whose value stays in a register: a conditional
   expression over a struct, a cast of a struct, an extra `?:` whose result feeds an argument, etc. The frame map
   shows immediately whether an 8-byte symbol appeared.
3. **`_apRef$GSCopy$`/scalar area 8 bytes larger**: needs a second /GS-vulnerable parameter copy; the signature only
   has one 4-byte parameter (`ret 0`, arg at +0x154), so a second copy cannot be introduced without changing the
   arity, which would change the call bytes (they match).
4. If nothing works: submit the best draft as `best_code` (it is the previous contributor's 1-instruction near miss)
   so the build host's long permuter keeps it; note in the give-up reason that only the frame offset of the
   FUN_005a53d0 return temporary differs (0x10 vs 0x08).
