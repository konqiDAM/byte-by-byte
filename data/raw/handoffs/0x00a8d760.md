# Addendum — run 2026-11-12 23:34-23:50 UTC (claim clm_9b982653196f464cbfcd, Beam Free/DeepSeek V4.1 Flash)

## Headline: the pack's own `addOffset()` / `getOffset()` helpers were never used. They split the defect.

`unit_866ef5ccb5e9.cpp` lines 1514-1522 provide, right next to this function's declaration:

```cpp
static __forceinline float addOffset(float a, float b) { return a + b; }
static __forceinline float getOffset(const AnimationTimingInfo& i) { return i.m_startTimeOffset; }
```

All 323 earlier variants hand-rolled the offset as `*(const volatile float*)&input.m_startTimeOffset`.
Swapping the loop body to the **non-volatile** helper form

```cpp
startTimes[f-…] = startTimes[f-…] + getOffset(input);   // equivalently addOffset(elem, getOffset(input))
```

keeps **extent 951, errors 0**, and **fixes the head's `mov edi,[esi]` order** — `mov edi` is now
`+0x22e`, exactly as in the original. The body elements 2-4 stay byte-identical. The single remaining
defect **moves to the head's x87 operand roles**:

```
ORIG   +0x22e mov edi,[esi]   +0x230 fld [ebp+0x1c]   +0x233 mov ecx,eax  +0x238 fadd [edi+ecx*4]
HELPER +0x22e mov edi,[esi]   +0x230 mov ecx,eax      +0x235 fld [edi+ecx*4] +0x238 fadd [ebp+0x1c]
VOLATL +0x22e fld [ebp+0x1c]  +0x231 mov edi,[esi]    (current best: order defect, roles right)
```

So the head has exactly **two mutually exclusive failure modes**, both one pair of instructions:

| offset spelling | head order | head roles |
|---|---|---|
| volatile cast (current best) | fld before mov — **WRONG** | fld=off, fadd=elem — right |
| `getOffset(input)` / plain field | mov before fld — right | fld=elem, fadd=off — **WRONG** |

The volatile read is what forces a discrete `fld` (roles right) and also what lets the scheduler hoist
it to the block head (order wrong); the non-volatile read keeps the m_data load first (order right) but
the compiler then picks the element as the accumulator (roles wrong). **The original needs a discrete
offset load that is not hoistable** — that is the whole remaining problem, and it is now a much
narrower statement than "class 2 liveness".
