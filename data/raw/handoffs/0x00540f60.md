## What the bytes say (mapped from `out\00540f60\orig.txt`, the ORIG listing)

Frame: `sub esp,0x730`; slots kind=+0x28 (0xffff), offset=+0x18, line=+0x1c, cur=+0x20,
**f=+0x24**, reference spill=+0x2c, `LineBuffer j`=+0x30..0x72b (0x710, needs the `char` buffer so
the extra /GS frame cookie appears), try-level=+0x74c.

Registers in the ORIG: esi=this, edi=script, ebx=**f** (the ParseBlock in/out counter, register-cached,
home +0x24), ebp=**pos** *and* the materialised zero constant (disjoint live ranges: `xor ebp,ebp`
at 0x0110 re-materialises the zero for cmp/`m_pGlobal=0`/`len=0`, then 0x0146
`mov ebp,[esp+0x18]` loads pos, 0x018f `add ebp,[esp+0x14]` (pos+=len), 0x0193
`cmp ebp,[edi+0x20]`, 0x0196 store offset).

So the ORIG keeps **f in ebx with a real home slot**, and at 0x00ef `xor ebx,ebx` is f's own init,
whose spill at 0x00fb stores **ebx** (the variable), while every other zero store uses the ebp
constant. Our draft stores the constant at 0x00fb and therefore the branch at 0x0144 uses the
folded `test` form. **One root cause, two instructions.**

Call signatures confirmed from the pushes (both are ScriptRunner members, no `add esp`):
`FUN_005400f0(Script*, int* kind, unsigned int* offset, unsigned int* len, Owner** cur, bool skip)`
`FUN_00540270(Script*, int kind, Owner* ref, unsigned int* len, unsigned int pos, int* f, int line, bool, bool)`
— note `&f` (+0x24) is passed to ParseBlock only (not to ParseOutput; ParseOutput gets `&offset`).
