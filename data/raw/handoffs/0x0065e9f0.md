## Hypotheses / next steps (priority order)

1. **Find the source construct that makes VC8 materialise a shared `0` in a callee-saved
   register.** This is the whole function. Note it is a *cost-model* decision: none of the
   6 uses needs a register (each has an immediate/`test` form), yet the original pays for

## 3. The residue, exactly

One **intra-block list-scheduler tie-break**. Same six instructions, same registers (ecx is
the `push` placeholder on both sides), same block boundary (`jge` at +0xD7 targets +0xDF on
both sides):

```
ORIG                          OURS

e2 d95e78   fstp [esi+0x78]    e2 6a01     push 1
e5 d9e8     fld1               e5 d9e8     fld1
```

ORIG hoists the `this` load of the *next* call above the `fstp` that ends the previous
statement, and computes the FP argument (`fld1`) before pushing the `bool`. Ours pushes the
bool first and loads `ecx` after it. **ORIG contains both orders in this same function**
(+0xBE loads `ecx` late, after `push 1`/`push ecx`; +0x1C4 hoists it above `add esp,0xc`),
so the order is decided by the scheduler, not by the source.
