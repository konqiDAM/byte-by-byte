## 3. The object model — do not re-derive this

`push -1; push 0xc73057` is a per-function `_except_handler4` thunk. It loads
`FuncInfo 0x00f34da0` (magic `0x19930522`, `maxState = 5`, unwind map at `0x00f34dc4`).
The five unwind actions name the whole object model:

| state | action | meaning |
|---|---|---|
| 0 | `push [ebp-0x44]; call 0x8dd170` | `operator delete` of the object — pool **5**, tag `0xe` |
| 1 | `mov ecx,[ebp-0x44]; add ecx,4;  jmp 0x917f50` | `Array<0x30-byte>::~Array` |
| 2 | `...[ebp-0x44]+0x10; jmp 0x917f50` | same, second 0x30 array |
| 3 | `...[ebp-0x44]+0x1c; jmp 0x96a370` | `Array<4-byte>::~Array` |
| 4 | `...[ebp-0x44]+0x2c; jmp 0x96a370` | same, second 4-byte array |

So: **there is no `__try`/`__except` and no C++ `try`.** The EH exists only because the function
does `new Q` where `Q`'s inlined ctor constructs four `Array` members with destructors and `Q`
has a class `operator delete`. `[ebp-0x44]` is the Q pointer spill (E-0x44); in a funclet `ebp`
is the frame base E. If you use **placement new** (`new (p) Q(...)`) MSVC emits **no** unwind
states and you get no EH prologue at all (that was attempt 1: 791 bytes). Use plain `new Q(...)`
with `Q::operator new` / `Q::operator delete`.

## 6. What did not work (do not repeat)

- **Placement new** `new (q) Q(...)` — no unwind states, no EH prologue, 791 bytes.
- **`extern "C" __declspec(dllimport) void* __stdcall TlsGetValue(unsigned long)`** — MSVC
  CSEs the import pointer into `edi` and calls `edi`, stealing the register the ORIG uses for
  `e4`. Use `extern void* (__stdcall* DAT_00d9b080)(unsigned long);` and call through it: that
  emits `call dword ptr [DAT_00d9b080]` at every site, exactly as the ORIG does. (The unit
  itself uses this idiom at lines 2384 and 3722.)
- **`Q54::Q54` not inlined** — the four `SetSize` calls become a separate out-of-line ctor and
  the extent collapses to 788 bytes. `__forceinline` on the ctor fixes it and puts the grows
  inside the `new` null check where the ORIG has them.
- **`if (h != 0)` vs `if (h)`, `if (d != 0)` vs `if (d)`, `if (block != 0)` vs `if (block)`** —
  no effect on the diff at all (1038 bytes either way).
- **`char* e4` / `char* key` instead of `void*`** — no effect; `key + 0x30` still came out as
  `add edx,0x30` rather than the ORIG's `lea edx,[ebp+0x30]`, because the value was already in
  edx and dead.
- **Hoisting the five pointer declarations to the top of the block and assigning later** (to
