## Why it looks unreachable with SP1 (opinion, for the record)

The original's loop head is `push ebx / mov eax,[esi] / test eax,eax / je / mov ebx,eax`: the load
result stays in the scratch `eax` and the *coloured* value starts at the copy in the next block.
Every spelling of the source that keeps the same bytes gives either a direct load into the coloured
register or two loads. In the whole shipped listing, a load is only ever split from its register
when the load sits above the shrink-wrap `push`, which is not the case here. Two sessions and
~1400 variants have not found a source shape that produces it.

Best guess if someone continues: the difference is a build-level artefact of that one function
(a different compiler build for that translation unit - AGENTS.md notes the GOG image has a few
small functions that differ from the Steam build). A `compiler_mismatch` / `instruction_order`
give-up is the honest category. The site's own solver is worth pointing at `exp91/x2/w01.cpp`
(it has the original's `tmp = item;` scheduling as well, and only differs in the five lines above).
