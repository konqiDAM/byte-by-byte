## What was measured (all via `exp91\score_pack.py`, ~26 shapes)

* **The clean shape without the reload is a 24-diff perfect mirror**: `node` in **edi**, `item` in
  **esi**, every other instruction identical (`mov edi,[ebp]` / `push edi` first, etc.).
  So this is *only* the two callee-saved registers of the two call-crossing webs.
* **Every source spelling of the clean shape gives that same 24-diff mirror**, byte for byte:
  plain `T* item = node->unk00`, `const` item/node, `(void*)current`, `T* current(item)`, nested
  scope for `current`, `result` declared before/after, `int result(0)`, `for(;;){}`, `(T*)node->unk00`
  cast, `while (node = node->unk04)`, `if (!item)` vs `if (item == 0)`, `if (item->FUN_0040ac60())`
  vs `!= 0`, named receivers for both `unk00` re-reads, a named `flag`/`code` local for the compare,
  plain second read of `node->unk00` (CSE'd away — no flip), `__forceinline` accessor for the item
  read, `__forceinline` accessor for the head (both used twice), `volatile` on the node reads,
  volatile-`current` local, volatile store into `current`.
* **The only thing that flips the colouring is a second *machine* load of `node->unk00` in the loop
  head block.** It raises `node`'s cost above `item`'s (per compiler_tips "Registers: colouring by
  cost": cost = uses × P × block frequency), so `node` takes `esi` — exactly the original's
  assignment. But that load is precisely the instruction the original does not have.
* The `__forceinline` double read (`node->Item()` twice) flips the colours **and** gives the right
  bytes everywhere except that one instruction: `ndiff=2` — because the store of the escaped local
  `current` (an address-taken local) is ordered **before** the reload (compiler_tips: a store into a
  local whose address escapes is linked to every later pointer load, so the load waits behind the
  store). Fixing the order needs the receiver to be the *register* copy, which is the target, which
  is the thing that will not happen without dropping the load.
* The reverse (making the *only* item pointer the escaped local, `current = node->unk00`, used for
  everything) is worse: an escaped local never gets a register home — the compiler keeps it in
  `[esp+0xc]`, re-reads it before each call, `this` moves to ebx, extent 96.
* `while (node) { ... }` produces **two epilogues** (extent 100). The single-epilogue shapes are
  only `if (node) { do { ... } while (node); }` and `for (;;) { if (!node) break; ... }` — both give
  the same 24-diff mirror.
* `node = unk00->unk04;` at the loop end (instead of the two statements) drops to extent **90**.

## Why I stopped

The evidence is a clean dichotomy: **24-diff mirror with one load** vs **1-diff with two loads**.
The original has one load *and* the flipped colours, so whatever produced the extra use of `node` in
its source emitted no instruction — nothing in the reachable source space (26 shapes above) does
that. This is the "the compiler chose differently and the source cannot reach it" case of
lessons-rival-code §10 (class 2/4). Per §12.4 the suggested lever for this address ("bind the item
to a named local before the loop") was tried in three forms and made the extent worse (97–100).
