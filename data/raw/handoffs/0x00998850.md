Why it is two functions (not one): body A ends with `ret` at +0x6f and nothing in the 273 bytes jumps to
+0x70; body B starts `push esi; mov esi,eax` — it consumes `eax` as an argument and ends with its own
`ret` at +0x110. `0x009988c0` is not in `function_index.json` at all (it is swallowed by the span).
This is the same defect the open `index_problem` report of 2026-11-08 describes; it is now *proved*,
not just suspected.

## What worked

1. **`--pack` pins addr/size/symbol**, and the pack's unit keeps a `static` stub body for the target, so
   `f3check` refuses a candidate that redefines it in the same namespace (C2084) — but the stub is
   `static` and unreferenced, so it is **not emitted**. Defining the target at **global scope** works,
   and the checker's "the target's own name" rule picks the emitted one. Qualify pack types
   (`f3m_00998d40::State`) — `using namespace` makes `DAT_00d9b080` ambiguous (C2872, it is declared in
   several scopes of this staging unit).
2. **Both bodies are private register conventions, not stack parameters.**
   ```cpp
   static __declspec(noinline) Record998* FUN_00998850(State* state) { ... }
   volatile State998* g_state998; volatile Record998* g_rec998;
   void caller998() { g_rec998 = ::FUN_00998850((State998*)g_state998); ... }
   ```
   A global function takes `state` from `[esp+8]` and pushes `edi` (119 B, 7 diffs). The `static` +
   caller form gives **`state` in `edi`, no prologue** — byte-exact at once. Body B's pointer is in
   **`eax`** the same way. The caller must call `::FUN_00998850` (ADL also finds the unit's namespace stub
   → C2668).
3. Body A body = the pack draft unchanged; `SlabArray::Append` (in-class) inlines to the same bytes.
4. Body B, the four things that each removed the last diffs:
   - **tail is an inlined member** (`this = &st->arr`) so `lea edx,[esi+4]` is emitted once and the tail
     reads `[edx+4]`/`[edx+8]`/`lea eax,[edx+0xc]`. Needs `__forceinline` (a plain member is not inlined:
     `jmp Shrink`).
   - **the field at `arr+0xc` (State+0x10) is real**: the dead arm passes `&unk0c`, so `State` is 4 bytes
     longer than the pack's stand-in. Declared `void* unk0c;` at its offset.
   - `if ((capacityFlags & 0x80000000u) != 0) return;` → `test esi,esi; js`. The `< 0` spelling gives `jl`.
   - **the count decrement must go through a reference**: `int& n = st->arr.count; n = n - 1;` emits
     `add dword ptr [esi+8],-1`; `st->arr.count--` (and `--x`, `x -= 1`, `x = x - 1`) all emit
     `add eax,-1; mov [esi+8],eax` (+2 bytes). Measured in a 4-variant toy TU.
   - `unsigned int x = count + 3;` then the 5-step smear `x |= x>>16/8/4/2/1` and `+1` is the round-up,
     spelled exactly as the listing shows.

## What did not work

- Defining the target inside `namespace f3m_00998d40` → C2084 (the unit keeps the stub body).
- `using namespace f3m_00998d40;` → C2872 ambiguous `DAT_00d9b080`.
- Unqualified call to the target from the caller → C2668 (ADL).
- Plain member `Shrink()` (not `__forceinline`) → real call, tail missing (extent 65).
- `st->arr.count--` / `--st->arr.count` / `-= 1` / `= count - 1` → register-form decrement (+2 bytes).

   convention functions are not emitted.
3. If the index is fixed to 112 only, body B still needs its own claim at `0x009988c0`; the body in
   `cand.cpp` is already exact for it.
4. Do **not** try to stretch body A to 273 bytes: after `ret` at +0x6f the original has no incoming
   jump, so no single function can produce those bytes.
