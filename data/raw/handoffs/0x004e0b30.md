## The bracket (the proof, class 5)

Every shape that moves the pick to `eax` does so only when the `NiPointer::obj` value stops being
the same node as `esi`, i.e. when the dtor re-reads it from its stack slot:

```cpp
// flips to lea eax,[esi+4] — but 362 bytes:
~NiPointer() { if (obj) { volatile long* rc = (volatile long*)&obj->refCount;
                           if (InterlockedDecrement(rc) == 0) obj->DeleteThis(); } }
~NiPointer() { if (obj) { unsigned int* c = &obj->refCount;
                           if (InterlockedDecrement((volatile long*)c) == 0) obj->DeleteThis(); } }
```
Both go 362 B because the DeleteThis `this` then becomes `mov ecx,[esp+0x14]; mov edx,[ecx]`
(+2 bytes) instead of `mov ecx,esi`. So:

* 360 B **and** `mov ecx,esi` (object stays in esi)  → allocator picks **ecx** every time;
* `lea eax` (object reloaded from the stack)          → costs **+2** (362 B).

The original is 360 B *with* eax: the two features the compiler will not emit together. That is the
§1 class-5 signature (`165 = 161 + 2 + 2` arithmetically, here `360 = 362 - 2`), on top of a class-2
(eax availability) mechanism.

## Analysis worth passing on

In the dtor block the register costs are eax 2 uses, ecx 1, edx 1 (eax = call result + vtable load,
ecx = `mov ecx,esi`, edx = `mov edx,[esi]`). The original picked the **most** expensive register
(eax), which is only possible if eax was on the allocator's free list as the *last-freed* register -
i.e. the original's `val->unkAC` load node (which occupies eax at 0x00c9 and dies at 0x00cf) was
still "warm" when the lea was coloured. Nothing in the source spelling of this function changes that
free-list state: 10 families, 730 variants, all identical.

## Correction to the bracket proof 2026-11-13T13:45Z (claim clm_ce4ebd65b0e94a77898d)

**The "+2" in `360 = 362 - 2` is not the lea.** A new variant closes the pick at 362 B *with*
`mov ecx,esi` intact, which the section above calls impossible:

```cpp
if (pKey && val && val->unkAC->type - 2 == 0)    // sweep12.py, variant "sub2"
```

```
 00cf  ORIG  cmp dword ptr [eax + 4], 2          4 B
 00cf  sub2  mov edx,[eax+4] ; sub edx,2         6 B   <- the +2
 00e6  sub2  lea eax,[esi+4] / push eax          target pick
 00f5  sub2  mov ecx,esi                         intact, no reload
```

So there are **two independent flip mechanisms, both costing exactly +2**: (a) the object reload
(`twostep`, `addrofref`: `lea eax` + `mov ecx,[esp+0x14]`), and (b) the arithmetic compare above.
`360 = 362 - 2` was arithmetic coincidence, not a compiler contradiction.
