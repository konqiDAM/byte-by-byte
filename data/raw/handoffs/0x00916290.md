### Key finding: `and esp,-16` IS reproducible from clean C++ on MSVC9 SP1
Prior sessions concluded it was irreproducible. WRONG. Two source-level triggers verified empirically:
1. An inlined SSE call passing __m128 by value (e.g. `static __forceinline void sa(__m128){}` called
   with `_mm_set_ps(...)`) — the aligned frame survives even when ALL xmm ops are optimized away at /O2.
2. A native `__declspec(align(16)) int adj[4];` local array (no SSE header needed).
Both produce MSVC9's 16-byte-aligned stack on this function shape -> the aligned EBP frame appears.

### New best: 212B vs target 222B (was 208B) — files `best_aligned.cpp` / `v_i2.cpp` @ /O2,/Oy-
Aligned frame reproduced; remaining 10B gap = prologue register-preservation + frame size ONLY:
* ORIG prologue: `push ebp; mov ebp,esp; and esp,-16; sub esp,0x14` (clean) with ebx/esi/edi saved MID-FUNCTION.
* MINE prologue: MSVC9 SP1 emits the realignment-preservation idiom instead:
  `push ebx; mov ebx,esp; push ecx; and esp,-16; add esp,4; push ebp; mov ebp,esp; sub esp,0x18`.
  Triggered because this/arg pointers are live across the aligned region in my source shapes.
* Frame: ORIG 20B (3 int slots + 4B align pad) vs mine 24B.

### Proven NOT to change the prologue shape (all on MSVC9 SP1 x86):
O0/Og/O1/O2 x Oy- x Ob1, SSE-helper placement (entry/mid/end), operand order flips, sign-extraction-first,
V4i copy of this, aligned int/float arrays, explicit zero float ref. The register-pressure timing that makes
ORIG defer its 3 callee-saved saves to mid-function is a compiler-internal scheduling decision not reachable
from source on SP1 for this shape (no calls in function; only x87 + integer ops).

### Exact remaining diff regions (best_aligned.cpp /O2,Oy-)
R1 prologue ~10B: preservation idiom + sub esp,0x18 vs 0x14. R2 register names for the four adjusted ints.
Body logic/flags/stores otherwise structurally matched; x87 ST usage close (ORIG keeps early fldz zero ref).
