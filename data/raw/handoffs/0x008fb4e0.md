# 0x008fb4e0 — `symbol_problem` cracked: the "mis-declared symbol" is the pack's own mangled name

**Status: MATCH and submitted** (`sub_6a9067bcd00943eead2c`, claim `clm_35d53555b0cf4786b65c`).
167 bytes, `__cdecl`, 4 int args, flags `/MT /O2 /GS /EHsc /Gy`.

## The real cause

The flag said *"the required symbol's calling convention, arguments or return type cannot produce
the original code, so no definition can match"*. That is not what was wrong.

`pack.json` names the symbol f3check must find in your object:

```
?CreateResourceObject@fnv_00c89540@@YAPAUFUN_00c894d0@1@HHHH@Z
```

f3check looks that name up **in your `.obj`** (`coff.named(sname)`); when it is absent it prints
`compiled but symbol ... not defined` and compares nothing. The name is decodable, and C++ can
produce it exactly:

| mangled piece | meaning |
|---|---|
| `?...@fnv_00c89540@@YA` | free function, `__cdecl`, in **namespace** `fnv_00c89540` |
| `PAU FUN_00c894d0@1@` | returns pointer to **struct** `FUN_00c894d0` **nested in that namespace** (`@1@` = enclosing scope) |
| `HHHH` | four `int` parameters |

So the fix is source shape, not a declaration hack:

```cpp
namespace fnv_00c89540 {
struct FUN_00c894d0 { /* sizeof == 0x2c */ ... };
FUN_00c894d0* __cdecl CreateResourceObject(int first, int second, int resourceId, int finalArgument);
}
```

`struct` matters: `class` mangles as `PAV...` and f3check still reports "not defined".
Nothing else was needed: the shared symbols file does **not** need an entry for this name —
`derive_bindings` takes the address from the original's relocation bytes for any name it has no
canonical binding for, so the function itself binds by construction.

## The rest of the function (the twin was 95% right)

FNV twin `0x00c89540` (`src/staging/blk_00c80000_o2.cpp:3563`) is the right **build variant**
(`_o2`, /EHsc, x87-free) — port its statement order verbatim in shape:

```cpp
FUN_00c894d0* __cdecl CreateResourceObject(int first, int second, int resourceId, int finalArgument)
{
    FUN_00c894d0* result = 0;
    if (resourceId != 0) {
        int info = bhkUtilFunctions_FindNextCollisionObject(resourceId);
        if (info != 0)
            result = new FUN_00c894d0(first, second, resourceId, info, finalArgument);
    }
    return result;
}
```

* **Drop the twin's `ScopedMemoryMode scopedMode(16)`.** The F3 bytes contain **no TLS access at
  all** (the twin's ctor/dtor write `g_tlsMemoryMode`). This is an engine-version difference, not a
  build variant. The pack unit's `TlsFlagGuard`/`g_tls.m_2b4` is the pack author's guess for the
  same idea and is likewise not in this function.
* The `/EHsc` frame the original *does* have (push -1 / handler / fs:[0], state set right after
  `operator new`, three exits via `0x008fb470+0x70`) is the **"free the allocation if the
  constructor throws"** cleanup that VC2005 emits for every `new T(...)` under `/EHsc`. No local
  object with a destructor is involved; write the plain `new` and the frame appears.
* `new` must go through the class's own allocation function, or you get the CRT's
  `??2@YAPAXI@Z` instead of `push 0x2c; call 0x0089eb90`:

  ```cpp
  static void* operator new(unsigned int count) { return FUN_0089eb90(count); }
  ```

  `FUN_0089eb90` is already declared in this pack's unit (line 372) and the shared file binds a
  hundred `??2<Class>@@SAPAXI@Z` names there, so any of them binds.
* `sizeof(FUN_00c894d0)` must be `0x2c` (that is the `push 0x2c`): vptr + `int m_04` of the base
  plus 9 more `unsigned int` members. The ctor at `0x008fb470`
  (`??0FUN_00c894d0@@QAE@HHHHH@Z`, `__thiscall`, five ints) is a canonical binding, so just
  declaring it is enough — do not try to write its body.
* `bhkUtilFunctions_FindNextCollisionObject(int)` — the call at `0x008f1d20`. Note the shared
  file **mis-binds that address** to `?FUN_00c802d0@@YAPAUMyNode@@PAU1@@Z` (one pointer arg,
  returns `MyNode*`). It did not matter: the name I used has no canonical binding, so f3check
  took the target from the original's bytes.

## Recipe for the rest of the category

1. Decode the required mangled name from `pack.json` (`undname`, or the table above). Get the
   scope (namespace or class), `struct` vs `class` (`U` vs `V`), the calling convention, and the
   argument list **exactly**.
2. Write the definition with that exact shape. If the name is nested in a namespace, open the
   namespace; if it is a member, make it a member of a struct with that name.
3. Never "work around" a mis-bound *callee*: any name f3check has no canonical binding for is
   bound from the original bytes. Only a name that **is** in the shared file with the wrong address
   can hurt, and then the anonymous/`extern "C"` self-declaration (the `DAT_00fdf044` trick from
   `0x009c7730`) is the escape.
4. Everything else about the function is normal work: read the FNV twin, port the structure, and
   drop the parts the F3 build does not have (TLS guards, monitor timers, extra asserts).
