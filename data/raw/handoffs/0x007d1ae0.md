The fix is an **inline forwarder whose parameters are declared in reverse order**. C++ initialises
function parameters **left to right**, while call arguments are evaluated **right to left**; inlining
the forwarder therefore loads `ref`, then `refID`, then the receiver, and defers the pushes to the call:

```cpp
__forceinline bool F4(Ref* r, unsigned id, Actor* a, Process* self) { return self->FUN_0072ff10(a, id, r); }
...
if (F4(ref, ref->refID, actor, actor->process))
```
gives `mov eax,[esi+0x10] | mov edx,[eax+0x1c] | mov ecx,[ebx+0x60] | push eax | push edx | push ebx | call`
— byte identical. This is the general lever for "the original allocates `ecx` before the argument
temps": wrap the call in a `__forceinline` forwarder and list the parameters in the order you want
them evaluated. See `progress/0x007d1ae0.md` for the variants that also matched (w2/w4/w8/w12/w14) and
the ones proved dead (scratch-struct conversion operators are elided — the "add one" dial does not
fire on single-member temporaries; volatile-ref forwarders kill the inlining).
