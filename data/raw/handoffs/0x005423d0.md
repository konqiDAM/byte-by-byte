## Part 1 — the C2511 compile error: FIXED (verified)

The bytes were already right; the rejection was a **declaration-order bug**, not a wrong signature.

Old order:

```cpp

    bool FUN_005423d0(TESFile* apFile);   // (A) TESFile not yet declared here
};
struct TESFile { ... };                   // (B) the definition
bool BGSBodyPart5423::FUN_005423d0(TESFile* apFile) { ... }   // (C)
```

At global scope this is legal: `h_74712c1d3c73.h` forward-declares `class TESFile;` globally, so
(A) binds to that incomplete `::TESFile`, (B) completes it, (C) matches (A). f3check compiles at global
scope, so it said MATCH.

The site pastes the candidate **inside `namespace f3m_005423d0 { ... }`**, so:

* (A) finds no `f3m_005423d0::TESFile` yet -> binds to the header's **global** `::TESFile`;
* (B) creates a *different* type, `f3m_005423d0::TESFile`;
* (C) resolves `TESFile` to the namespace one -> matches no declaration -> C2511.

**Fix:** moved `struct TESFile { ... };` above `struct BGSBodyPart5423`. Nothing else changed; member
offsets and the body are untouched, so the bytes are identical (MATCH 804/804 re-confirmed).
