## State of the diff (the whole residue)
Everything matches instruction-for-instruction **except one register rotation**:

| value | ORIG | ours (w7) |
|---|---|---|
| `a` / `ref` / `target` | **esi** | esi ✓ |
| `node` | **edi** | edi ✓ |
| `cell` | **ebx** | **ebp** |
| `result` / `item` | **ebp** (shared) | **memory** (`item@0x14`, `result@0x18`) |
| constant 0 | *(none — rematerialised)* | **ebx** |

Consequences: `cmp reg,ebx` where ORIG has `test reg,reg` / `cmp [mem],0`; `mov ecx,ebp` where ours
reloads `mov ecx,[esp+0x14]`; the guard path gets a separate `xor eax,eax` epilogue instead of
jumping to the shared `mov eax,ebp`; slots 0x14/0x18 of item/result are swapped; +13 bytes (527).

**Diagnosis:** in ORIG all four callee-saved registers are occupied by real webs
(`a, node, cell, result/item`), so VC8 cannot hoist the constant 0 into a register and rematerialises
it (`test`, memory-immediate `cmp`). In ours only three webs need a callee-saved register, so the
constant 0 is hoisted into **ebx**, `cell` is pushed to `ebp`, and `item`/`result` are spilled. Kill
the constant's register and the whole rotation should fall into place.

**Levers already tried and inert** (all extent 527): declaration order of
`count/list/cell/node/result` (7 permutations), `return 0` vs `return result` in the guard,
`node`/`result` declared before the guard, `item` declared inside vs outside the loop, a named
`Info* info` local, a named `unsigned flags` local, `node->next == 0` spellings, `while (node != 0)`,
`count != 0`, `list.FUN_00645c20() == false`, merged `if (count && !IsEmpty)`,
`count++` before/after the append, `for` vs `while` in the pick loop, `i`/`index` order.
(`--permute` was not used — it is banned for this run.)

## KEY LEAD found at 19:10Z — the flip is the *number of zero uses*, and it is one edit away
`q3_noctor_assign_only.cpp` (the same body but the `List` has **no constructor and no explicit
zeroing of its two fields**) compiles to **511 bytes with ORIG's register pattern exactly**:

```
xor edi,edi / cmp esi,edi / mov [esp+0x14],edi      <- zero = edi (node's), result slot 0x14 ✓
guards use edi ✓        xor ebx,ebx (cell = ebx ✓)   test eax,eax ✓   lea edi,[eax+0xac] ✓
```
i.e. no hoisted constant, `cell` in `ebx`, `result` at slot 0x14, `test` instead of `cmp ...,ebx`.
Adding the two list-zeroing stores back (`q4_agginit` with `List list = {0,0};`, `q5_assign` with
`list.item = 0; list.next = 0;`, or the ctor form `w7`) flips the allocator back to the wrong
pattern: the constant 0 gets **ebx**, `cell` is pushed to `ebp`, `result`/`item` spill, extent 527.

So the whole residue is **one cost tie**: with two extra uses of the zero constant in the entry
block, VC8 hoists a dedicated zero register and the four callee-saved registers rotate. ORIG has
those two stores *and* keeps the good allocation, so the next lever is to reduce the zero-constant
uses by two somewhere else (or raise `result`'s cost so it keeps `ebp`), e.g.:
* express the list zeroing so it does not need the zero register (a `memset`-shaped form, a ctor
  whose stores VC8 schedules differently, or `List list = {0, 0}` with the ctor present),
* drop one of the other zero uses (`count = 0`, `cell = 0`, `result = 0`) and re-add it in a shape
  that does not use the constant register,
* `exp91\p_dtor2.cpp` is the micro probe for how the ctor/dtor pair changes the entry block.
