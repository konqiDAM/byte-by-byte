## NEW EVIDENCE THIS SESSION: VC9 SP1 never coalesces a scalar-new `$T` with a named local

Three probes in `C:\f3decomp\out\0x0049e490\` (compile them with
`python win_tools\msvc9.py /c /nologo /MT /O2 /GS /EHsc /Gy /Fa <f>.cpp /Fo<f>.obj`, then read the
`$T` equates at the top of the `.asm`):

* `probe1.cpp` / `probe2.cpp` — `T* p = 0; ... p = new T(true); ...` with a class-specific
  `operator new` calling the game heap. Every spelling gives two symbols: `$Tnnnn` and `_p$`.
* `probe3.cpp` — a faithful miniature of this function (ebp frame forced by `_alloca`, a switch over
  chunk IDs, a sibling arm that reads `p`, the whole trailing list walk). Result:
  `$T2633 = -28`, `_p$ = -24` — **still two slots**. The temp takes the slot *below* the local,
  exactly like our candidate's `-0x18`/`-0x1c`.
* So no spelling of `pointList = new PtList_49e490(true)` will ever move the `+0x14f` store.

What *does* coalesce (proven this session): **named local -> named local**. Variant
`out\0x0049e490\v08.cpp` inserts a named `PtList_49e490* made = new ...; pointList = made;` — VC
merges `made` into `pointList`'s slot and drops the copy, and the diff stays at exactly the same 3
(the `$T` temp survives). That is the useful lever for the next agent: the original's `+0x14f`
store must belong to a **named** symbol, not to `$T`.

## What the next agent should try (hypotheses, not yet measured)

1. **An inlined function whose own local *is* the destination.** The `$T` never merges with a named
   local, but an inlined body's locals are allocated by a different (inline) slot allocator and can
   take the caller's slot. Write the arm so the raw allocation result is a *parameter/local of an
   inlined body* that the caller passes `&pointList` to, e.g.
   an `__forceinline void LoadPointList(PtList_49e490** slot, unsigned d)` that does
   `*slot = new PtList_49e490(true); (*slot)->FUN_004a2720(d);` — check whether the inlined body's
   `$T` lands in the caller's `pointList` slot (`y02` inlined a factory that *returned* the pointer
   and did not; passing the **address of the destination** into the inlined body is the untested
   half).
2. **Two named locals, one slot.** Since named->named coalescing works, get the +0x14f store into a
   named local that merges with `pointList` *and* keep the new-expression's temp dead: e.g. give the
   class a `__forceinline static PtList_49e490* Alloc(unsigned n)` used through an explicit
   `operator new` spelling so that the raw pointer is a named local, and let the second store come
   from the new-expression. Watch the instruction order at +0x14f..+0x177 — the original interleaves
   them (`cmp`/trylevel/`je`/ctor/`xor`/`mov ecx,[ebp-0x14]`/`push`/`mov ecx,eax`/trylevel reset/
   store) and a shape that produces any additional `push` or `lea` will not score 3.
3. Do **not** re-derive: `throw()` on `operator new`, removing `operator delete`, `static`, a
   `PtList*` return type, declaration-order swaps, bare blocks, comma/ternary/`if` assignment forms
