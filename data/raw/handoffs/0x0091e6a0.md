### Changes that worked (kept)

### START HERE: `if (impulse < 0.0f)` (worth ~30 of the 57 differing instructions)

`R4`/`R5` differ because our candidate leaves **one extra live x87 slot** at the `if (impulse<0)` merge.
ORIG at the merge (`0x91ea1b`) has depth 1 = `[factor]`; ours has one more and therefore emits
`fld st(0) / fld [esp+0x70] / fld st(0) / fmulp st(2) / fxch st(1) / fstp [out.i]` (5 insns per component)
where ORIG emits `fld [esp+0x70] / fld st(0) / fmul st(2) / fstp [out.i]` (4 insns).

What ORIG actually does: `fld [normal.i]; fld st(0); fmul st(N)` **keeps** the loaded `normal.i` on the
x87 stack (`fmul st(N)`, no pop) and accumulates `nx, ny, nz, nw` across the whole block, then **consumes
them in the DAT correction** at `0x91eb19..0x91eb2b` (`fmul st(1) / fadd [esp+0x48] / ... / fmul [esp+0x7c]`).
So in ORIG `input.m_normal` is **live across the scale+correction block as x87 values**; in ours it is
reloaded. The lever is making the four normal components live across that block, not the scale itself.

Devices to try, in this order:
1. **section 20.17** - name the factor a local **and** put an address-of something between the value and the test
   that consumes it, then use it after the merge. (Tried the named local alone: `float factor =
   input.m_objectImpulse;` - **inert**, VC8 folds it. The pair is the point.)
2. **section 19.71** - a volatile read is a hard scheduling barrier and buys exactly one slot. If the merge needs
   its store one slot later this is the knob; free only if the displaced instruction already exists.
3. Check whether ORIG's value reaches the merge through a **conditional expression** rather than an `if` -
   that is what creates the phi in the first place. (ORIG's clamp already has the
   `fstp [esp+0x80] / fld [esp+0x80]` store-reload pair and ours matches it exactly, so the clamp itself
   is not the problem - the merge below it is.)

### The other three, after that

1. **R1/R2 - the Begin loop's address CSE.** ORIG `cmp [eax+edi*4],0 / lea eax,[eax+edi*4] / je /
   mov ecx,[eax]`; ours `cmp [eax+edi*4],0 / je / mov ecx,eax / mov ecx,[ecx+edi*4]`. Same instruction
   count, different bytes. **section 19.76: duplicate the expression at its use rather than caching it in a
   local**, so VC8 hoists exactly one unnamed temp. Tried and inert: `hkpCharacterProxyListener** pl =
   m_listeners + i; if (*pl) (*pl)->cb(...)`, and the named-local form (worse).
   Untried: a `listenerAt(int)` reference accessor like the twin's `ContactListener*& listenerAt(int)`.
2. **R5 - the mass dot product.** ORIG loads `[0x94]` (torque.x) first, then `[0xd8]` (transformed.y);
   ours loads `[0xe0]` (transformed.x) first. Both spellings tried: `torque.i*transformed.i` gives ORIG's
   term order but swapped operands; `transformed.i*torque.i` gives swapped term order. The asymmetric
   spelling `torque.x*transformed.x + transformed.y*torque.y + transformed.z*torque.z` measured
   **worse** (0.876). ORIG's pattern is genuinely asymmetric - term 1 loads torque, terms 2-3 load
   transformed.
3. **R5 - `diff` / `gravityVel` slots.** ORIG diff `0xa4`, gravityVel `0xb4`; ours the reverse.
   Declaration order is measured **inert** (top of function / next to `torque`: no change), and inlining
   the `operator-` temp into `setCross` is inert too. **section 20.00: a round 0x10 excess is alignment padding
   from the number of distinct `align(16)` locals - count them and merge two into one aggregate.**
4. **R7 - Post loop colouring.** ORIG keeps the listener in `eax` and the two `lea`s in `ecx` and ends with
   `mov ecx,eax`; ours is the mirror. The `pl` respell made it worse (0.886 -> 0.855). If it turns out to be
   the `cmp [mem],0` vs `cmp [mem],ebx` / `al` vs `bl` family (**section 20.14**), **report it and stop** - four
   functions died there after 25/10/7/5 inert variants.

### One more lead worth knowing
On a big twin that matched outright (`0x00a050e0`, 1183 B, all 5 regions) the decisive edit was removing a
**redundant copy** - a draft with `v = ProcessShape(...); n = v;` made VC8 hold one value in two registers,
re-coloured the whole function and cost 12 instructions. **Where a region looks structurally right but the
match percentage is low, look for two source names for one value before sweeping.** Candidate places here:
`other` (the PropertyValue) vs its `.get()`; `diff` vs the `operator-` temporary; `dt` vs
`stepInfo.m_deltaTime`.
